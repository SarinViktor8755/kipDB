Изменения: клиентский кеш списка приборов + HTTP ETag

Что изменено
------------
1. Клиентский список приборов сохраняется в localStorage браузера под ключом
   kip.devices.cache.v1.
2. При повторном открытии списка сохранённые данные отображаются сразу, до ответа сервера.
3. Запрос /api/devices отправляет If-None-Match с последним ETag.
4. Сервер возвращает 304 Not Modified без JSON-массива, если список не менялся.
5. Если данные изменились, сервер возвращает актуальный JSON + новый ETag.
6. SQLite-триггеры автоматически увеличивают devices_revision при INSERT, UPDATE
   и DELETE в таблице devices. Это охватывает также удаление и восстановление приборов,
   изменение фотографии и изменение местоположения.
7. Существующее gzip-сжатие ответа /api/devices сохранено.

Поведение
---------
- Первый запуск или пустой кеш: полная загрузка списка с сервера и сохранение кеша.
- Повторное открытие без изменений: мгновенный показ кеша и короткий запрос с ответом 304.
- После изменения любого прибора: сервер выдаёт новый ETag и полный актуальный список;
  браузер заменяет локальный кеш.
- Если localStorage недоступен или переполнен, приложение продолжает работать обычным
  способом, без постоянного кеширования.

Сборка
------
Проект рассчитан на Java 17+ и Maven. Из корня проекта:
    mvn clean package -Pprod

Исполняемый JAR должен появиться в target/kip.jar.

Исправление журнала изменений приборов:
- При редактировании теперь сравниваются и записываются в журнал все основные поля и все поля details_json.
- В частности, «Максимальная шкала» (scaleMax) и «Минимальная шкала» (scaleMin) отображаются под понятными русскими названиями с прежним и новым значениями.
- Аналогично журналируются тип датчика, единица измерения, категория, МПИ, класс точности, красная черта, даты, номер строки, группа, позиционное обозначение, фото и остальные поля details_json.
